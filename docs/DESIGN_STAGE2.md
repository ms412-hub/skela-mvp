# Skela Room v2.0 — 2단계 설계서: 가상 카메라 · 이미지/3D 에셋 변환

이 문서는 코드를 포함하지 않는 설계서다. 1단계 확정안(다층 `floors` 탭, Plan v2, 계단 위치 표시)을 전제로 한다.

## 0. 지키는 원칙 (1단계와 동일)
| 원칙 | 이 설계에서의 적용 |
|---|---|
| 내부 단위 `cm` 유지 | 카메라 위치·화각 범위·간격 모두 cm로 저장. **m 변환은 3D 파일을 쓰는 순간 한 곳에서만** |
| 기존 144개 테스트 보호 | 기존 모듈(`Plan`, `catalog`, `geometry`, `templates`)의 함수 시그니처와 결과를 바꾸지 않는다. 새 기능은 새 모듈에 둔다 |
| 100% 무료·로컬 | 서버·유료 API 없음. 모든 렌더링·변환은 브라우저 안에서. 사용 라이브러리는 이미 설치된 three.js 0.186.1(MIT) 내장 도구만 (선택 1개 예외: 묶음 저장용 `fflate`, MIT) |
| 계산과 화면 분리 | 카메라·잘라내기·해상도·파일명·크롭 계산은 three.js 없는 순수 함수 → 단독 테스트 |
| 결과물 저작권 자유 | 사용자가 만든 장면의 출력물에 워터마크·제약 없음 |

### 1단계에서 넘겨받아야 하는 것 (선행 조건)
- `project.cameras` 빈 슬롯 (1단계 확정)
- `project.floorGap` = 260cm (1단계 확정)
- **추가 요청 1건**: 배치된 가구(`Furniture`)에 선택 필드 `visible?`, `exportable?` (없으면 `true`로 간주). 선택 필드라 기존 데이터·테스트에 영향 없음. 2단계 내보내기의 "제외" 규칙이 이 값을 쓴다.

### 범위 밖으로 확정된 것과의 관계
- 유니티 연동은 제외 확정 → 기존 `unity/` 폴더와 `unityExport.ts`는 **삭제하지 않고 동결**(테스트 보호). 2단계의 GLB/OBJ가 엔진 중립 출력 역할을 대신한다.

## 1. 용어: 두 종류의 카메라를 절대 섞지 않는다
| 이름 | 무엇 | 저장 여부 |
|---|---|---|
| **편집 카메라** | 지금 화면(평면/3D/걷기)을 보는 카메라. 마우스로 돌리고 확대 | 저장 안 함 |
| **가상 카메라** | 사용자가 "이 시점"으로 저장한 촬영용 카메라(시점 북마크) | `project.cameras`에 저장 |

- 가상 카메라를 편집해도 편집 카메라는 움직이지 않는다.
- 연결은 두 가지 버튼뿐이다. 둘 다 **복사**이고, 서로 계속 묶여 있지 않는다.
  - "현재 시점으로 카메라 만들기/덮어쓰기": 편집 카메라 → 가상 카메라
  - "이 카메라 시점으로 보기": 가상 카메라 → 편집 카메라

## 2. 가상 카메라 데이터 (`project.cameras[]`)

| 필드 | 의미 | 값 / 단위 | 기본값 |
|---|---|---|---|
| `id` | 고유 ID | `cam1`, `cam2`… (기존 `nextId` 규칙) | — |
| `name` | 이름 | 1~30자, 프로젝트 안에서 중복 금지 | "카메라 1" |
| `preset` | 프리셋 | `interior` · `iso` · `illust` · `top` · `fps` | `interior` |
| `projection` | 투영 | `perspective`(원근) · `orthographic`(직교) | 프리셋 따름 |
| `pos` | 카메라 위치 | `{ x, y, h }` cm. x·y는 평면도 좌표, h는 **해당 층 바닥에서의 높이** | 맞춤 계산 |
| `target` | 바라보는 점 | `{ x, y, h }` cm | 맞춤 계산 |
| `fovDeg` | 세로 화각 (원근만) | 20~100° | 프리셋 따름 |
| `orthoSpan` | 화면에 보이는 세로 길이 (직교만) | 50cm 이상 | 맞춤 계산 |
| `aspect` | 화면 비율 가이드 | `16:9` · `3:2` · `4:3` · `1:1` · `9:16` · `{w,h}` | `16:9` |
| `floorScope` | 찍을 층 | `current`(지정 층 1개) · `stack`(전체 적층) · 층 ID 목록 | `current` |
| `floorId` | 기준 층 | 층 ID | 만들 때 선택된 층 |
| `cutaway` | 벽 잘라내기 | `{ mode: 'none' \| 'auto' \| 'manual', hiddenWallIds: [] , hideCeiling: true }` | `auto` |
| `output` | 이 카메라의 기본 출력 설정 | `{ style, background, size }` (5장 참고) | 프리셋 따름 |

### 2-1. 프리셋 기본값
| 프리셋 | 용도 | 투영 | 각도 | 화각/범위 | 잘라내기 | 기본 출력 |
|---|---|---|---|---|---|---|
| `interior` 인테리어 | 실내 사진처럼 | 원근 | 눈높이 150cm, 110cm 높이를 봄 | 60° | auto | 컬러 PNG |
| `iso` 아이소메트릭 | 설명도, 평면 입체 | 직교 | 방위 45°, 내려보기 35.26° (정등각) | 방 전체 맞춤 | auto | 컬러 PNG |
| `illust` 일러스트/게임 | 게임 에셋, 2:1 픽셀 아트 각도 | 직교 | 방위 45°, 내려보기 26.57° (2:1 다이메트릭) | 맞춤 | auto + 천장 숨김 | 컬러+선화, 투명 |
| `top` 탑다운 | 평면도 이미지 | 직교 | 바로 위 90°, 평면도와 같은 방향(위=평면도 위) | 맞춤 | 천장 숨김 | 컬러 PNG |
| `fps` 1인칭 | 걷기 시점 저장 | 원근 | 눈높이 160cm, 수평 | 70° | none | 컬러 JPG |

### 2-2. 검증 규칙 (순수 함수, 저장·불러오기 때 적용)
- `pos`와 `target`이 같은 점이면 거부 → target을 앞쪽 100cm로 보정.
- `fovDeg`는 20~100으로, `orthoSpan`은 50cm 이상으로 잘라 맞춤.
- 이름이 비었거나 중복이면 "카메라 N"으로 자동 변경.
- 존재하지 않는 `floorId`면 첫 번째 층으로 바꿈. 층을 지울 때 그 층만 보던 카메라는 첫 층으로 옮긴다(카메라는 지우지 않음).
- 카메라 최대 50개.
- 알 수 없는 필드는 버리고, 형식이 틀린 카메라는 그 카메라만 건너뛴다(프로젝트 전체를 거부하지 않음).

### 2-3. 마이그레이션
- `cameras`가 없거나 빈 배열 → 빈 배열 유지. **기본 카메라를 데이터에 억지로 넣지 않는다.** 카메라가 없을 때는 "현재 층을 `interior` 맞춤 시점으로 보는 임시 카메라"를 화면에서만 계산해 보여준다(저장 안 함).

## 3. 순수 계산 모듈 (three.js 없음, 단독 테스트)

| 모듈(제안 이름) | 하는 일 | 테스트할 것 |
|---|---|---|
| `camera.ts` | 프리셋 기본값, **맞춤(fit)** 계산(층 범위 + 비율 → pos/target/span), 검증·보정, 편집 카메라 ↔ 가상 카메라 변환값 계산 | 맞춤 후 방 네 모서리가 화면 안에 들어오는지, 각도(35.26°/26.57°)가 정확한지, 보정 규칙 |
| `cutaway.ts` | 카메라 위치와 층의 벽 목록 → 숨길 벽 ID 목록. 지금 편집 화면의 "카메라 쪽 벽 반투명" 로직을 옮겨 온 것. 30cm 여유(깜빡임 방지) 유지 | 방 바깥 네 방향에서 각각 앞쪽 벽만 숨는지, 여유 구간에서 결과가 바뀌지 않는지 |
| `stack.ts` | 적층 보기용 층별 높이: `층 순서 × floorGap(260)` | 층 순서 변경 시 높이 재계산 |
| `exportJob.ts` | 내보내기 작업 명세 계산: 최종 픽셀 크기, 타일 나누기, 포함/제외 대상, 파일 이름 | 비율별 크기, 타일 합이 원본과 정확히 같은지, 파일 이름에 금지 문자가 없는지 |
| `crop.ts` | 투명 이미지의 불투명 영역 경계 + 여백 계산 (픽셀 배열 입력) | 빈 이미지, 가장자리에 닿은 물체, 여백이 이미지 밖으로 안 나가는지 |
| `mtl.ts` | OBJ용 재질 파일(.mtl) 글자 만들기 (색 → `Kd`) | 같은 색 재질 합치기, 이름 규칙 |
| `assetFrame.ts` | 3D 내보내기 좌표 변환(cm→m, 축), 가구 단독 내보내기 원점(바닥 가운데) 계산 | 64평 템플릿 전체 범위, 회전 가구의 원점 |

## 4. 카메라 스튜디오 화면 (UI)

### 4-1. 배치
- 왼쪽 패널에 **"카메라"** 섹션 추가: 목록, `+ 현재 시점 저장`, 프리셋 선택 버튼 5개.
- 카메라를 고르면 오른쪽 **속성**에 카메라 필드(이름, 프리셋, 투영, 화각/범위, 비율, 층, 잘라내기, 기본 출력)가 나온다. 수치 입력은 기존 가구 속성과 같은 방식(바꾸면 되돌리기 가능).
- 3D 편집 화면에 **카메라 아이콘과 시야 범위 선**(보기 전용 도우미)을 그린다. 끌어서 위치 이동, 바라보는 점은 작은 공을 끌어서 이동.

### 4-2. 미리보기
- 화면 오른쪽 아래에 **작은 미리보기 창**(가로 320px, 고른 비율 그대로)을 둔다. 고른 가상 카메라로 낮은 해상도 렌더링.
- 갱신 시점: 카메라·가구가 바뀐 직후 + 끌기 중에는 초당 최대 10번(느린 기기 보호).
- **"카메라로 보기"** 토글: 메인 화면을 가상 카메라 시점으로 바꾸고, 비율 밖은 어둡게 가린다(레터박스). 이 상태에서 화면을 돌리면 확인 문구 "카메라 위치를 바꿀까요? [바꾸기] [보기만]"을 띄운다(실수 방지).

### 4-3. 층과 적층 보기
- 편집은 1단계 규칙대로 **선택한 층 1개만**.
- 적층 보기는 보기 전용 토글: 모든 층을 `순서 × 260cm` 높이로 쌓아 그린다. 바닥을 뚫지 않는다(1단계 제외 항목 준수). 적층 보기 중에는 편집 도구를 끈다.

### 4-4. 장면 프리셋 (2단계 범위)
- 2단계에서는 카메라 단위 설정(층, 잘라내기, 출력)만 저장한다. "카메라 + 조명 + 숨길 물체 묶음"인 장면 프리셋은 조명이 생기는 **3단계로 미룬다**.

## 5. 이미지 내보내기

### 5-1. 공통 원칙: 편집 장면을 건드리지 않는다
- 제미나이 초안의 "도우미를 잠깐 숨겼다가 원복"은 실패하면 화면이 망가질 위험이 있다.
- **대신 내보내기 전용 장면을 따로 만든다.** 같은 Plan 데이터 → 같은 상자 목록(`buildBoxes`) → 별도 three 장면. 격자·기즈모·카메라 아이콘은 처음부터 넣지 않는다. 작업이 끝나면 통째로 버린다.
- 포함 규칙: `visible !== false` 그리고 `exportable !== false`인 가구만. 벽·문·창문은 항상 포함(잘라내기 규칙만 적용).
- 렌더러: 내보내기 전용 WebGL 렌더러 **1개**를 처음 내보낼 때 만들고 재사용(브라우저의 WebGL 개수 제한 보호). 결과는 화면이 아닌 렌더 타깃(오프스크린)에 그린다.

### 5-2. 크기와 큰 이미지
| 이름 | 긴 변 | 16:9 예시 |
|---|---|---|
| HD | 1280 | 1280×720 |
| FHD | 1920 | 1920×1080 |
| QHD | 2560 | 2560×1440 |
| 4K | 3840 | 3840×2160 |
| 직접 입력 | 256 ~ 4096 | — |

- 기기의 최대 텍스처 크기를 먼저 확인한다. 넘으면 **타일 렌더링**: 화면을 2048px 이하 조각으로 나눠 각각 그린 뒤 이어 붙인다(카메라 시야 일부만 그리는 three.js 기본 기능 사용). 이어 붙인 결과는 한 번에 그린 것과 같아야 한다.
- 4K 한 장은 약 33MB 메모리를 쓴다. 폰에서는 QHD까지만 기본 허용하고, 4K는 "느릴 수 있어요" 안내 후 타일로.
- 계단 현상 방지: 선화가 아니면 2배로 그린 뒤 줄이기(최대 4096 제한 안에서), 선화는 선 굵기 보정만.
- 색: 편집 화면과 같은 sRGB 출력, 같은 조명.

### 5-3. 출력 형식
| 형식 | 배경 | 비고 |
|---|---|---|
| PNG | 배경색 | 기본 |
| JPG | 배경색 (투명 불가) | 품질 0.92. 투명을 고르면 JPG 선택을 막음 |
| 투명 PNG | 없음(알파 0) | 바닥까지 포함할지 선택 가능: "바닥 포함 / 가구·벽만" |
| 선화 | 흰색 또는 투명 | 아래 5-4 |
| 컬러+선화 | 배경색 또는 투명 | 평면 색 + 검은 윤곽선 (게임·일러스트용) |

### 5-4. 선화(윤곽선) 방식
- 가구가 상자·원기둥·경사면 같은 단순한 모양이므로 **모서리를 직접 선으로 뽑는다**(three.js의 모서리 추출 기능, 꺾이는 각도 30° 이상만). 이미지 후처리(가장자리 검출)보다 선이 깨끗하고 빠르다.
- 가려진 선 처리: 면을 흰색(선화) 또는 원래 색(컬러+선화)으로 먼저 그리고, 면을 아주 살짝 뒤로 밀어서 앞쪽 선만 보이게 한다.
- 선 굵기: 기본 1px 선은 4K에서 너무 가늘다 → three.js의 굵은 선 도구(MIT)로 **해상도 비례 굵기**(긴 변 1920 기준 1.5px).
- 1mm 떨림 방지 확대 때문에 겹치던 부품의 모서리가 아주 가깝게 두 줄 생길 수 있다 → 선화용 모서리는 1mm 이내로 붙은 같은 방향 선을 하나로 합친다(`exportJob` 단계에서 판단 기준만 정의, 구현은 3단계 전 테스트로 확인).

### 5-5. 가구 하나씩 스프라이트
- 고른 가구(또는 층의 모든 가구)를 **하나씩만 남긴 장면**에서 그린다.
- 기본 카메라: `illust`(2:1) 직교, 가구 범위에 맞춤, 투명 배경.
- 그린 뒤 불투명 영역만 잘라내고 여백(기본 8px)을 둔다(`crop.ts`).
- 같은 가구 종류는 같은 확대 비율로 그려서 크기 비교가 맞게 한다(옵션: "실제 크기 비율 유지").
- 여러 장은 ZIP 하나로 묶는다(`fflate`, MIT, 약 8KB). 이 의존성을 원하지 않으면 한 장씩 저장.

### 5-6. 파일 이름
`{프로젝트}_{층}_{카메라}_{가로}x{세로}.png`, 스프라이트는 `{프로젝트}_{가구이름}_{id}.png`. 금지 문자(`\ / : * ? " < > |`)는 `_`로, 공백은 `-`로, 최대 80자.

## 6. 3D 에셋 내보내기 (GLB / OBJ)

### 6-1. 좌표·단위 (외부 툴 표준에 맞춤)
- 오른손 좌표계, Y가 위, **1 = 1m**. 변환은 파일을 쓰는 순간 한 번만: 평면도 `(x, y, 높이)` cm → `(x/100, 높이/100, y/100)` m.
  - 지금 three.js 장면도 이 축 배치를 쓰므로 뒤집힘(거울상)이 없다. 위에서 보면 평면도와 같은 방향.
- 가구의 앞면은 +Z (glTF 권장 "앞" 방향과 같음).

### 6-2. 원점 규칙
| 내보내기 범위 | 원점 |
|---|---|
| 전체 프로젝트 | 1층 평면도의 (0,0), 1층 바닥 높이 0. 층은 `순서 × 260cm` 높이로 쌓음 |
| 층 하나 | 그 층 평면도의 (0,0), **그 층 바닥을 높이 0**으로 (옵션: 적층 높이 유지) |
| 가구 하나 | 가구의 **바닥 가운데**. 회전은 0°로 되돌려서(앞면 +Z) 저장 |

- 가구 원점은 **떨림 방지 확대(최대 약 1cm) 전의 원래 크기**로 계산한다. 그래야 외부 툴에서 바닥에 정확히 놓인다.

### 6-3. 떨림 방지 확대를 3D 파일에 남길지
- 남긴다(기본). 이유: Blender·Godot에서도 같은 평면에 겹친 면은 똑같이 지글거린다. 확대량은 1mm 단위라 치수 오차는 무시할 수준.
- 옵션 "원래 치수로 내보내기"를 두되, 켜면 겹치는 면이 생길 수 있다고 안내.

### 6-4. 파일 구조
- 이름 있는 묶음: `프로젝트 → 층(1F…) → 벽 / 문·창문 / 가구 → "침대 (furn1)" → 부품`.
- 재질은 색마다 하나만 만들어 공유. 창문 유리는 반투명 재질(glTF 표준 반투명 모드).
- 옵션 "가구 부품 합치기": 가구 하나를 메시 하나로 합쳐서 게임 엔진에서 가볍게.
- 제외: 도우미, 격자, `visible:false`, `exportable:false`.
- GLB: three.js `GLTFExporter`(MIT), 이진(.glb) 한 파일, 한글 이름 그대로.
- OBJ: three.js `OBJExporter`(MIT) + 우리가 만드는 `.mtl`(색). OBJ는 한글 이름이 깨지는 툴이 있어 **객체 이름은 영문 id**(`furn1_bed`), 한글 이름은 주석으로. 두 파일이므로 ZIP으로 묶음.
- 크기 예상: 64평 템플릿 약 340개 상자 → GLB 수백 KB 수준.

## 7. 파일 저장(다운로드) 경로 — 중요한 제약
- **claude.ai 아티팩트 화면에서는 파일 다운로드가 막혀 있다.** 그래서 아티팩트에서는 "미리보기 + 이미지 길게 눌러 저장"만 가능하다고 안내한다.
- 정상 다운로드는 **GitHub Pages 배포판**에서만 된다 → 2단계 시작 전에 작업 브랜치를 main에 합쳐 배포하는 것이 선행 조건.
- 배포판 저장 방식: 브라우저 기본 다운로드. 폰에서 사진첩 저장이 필요하면 공유 시트(브라우저 기본 기능, 무료)를 옵션으로.

## 8. 안전장치와 성능
- 내보내기는 진행률 표시 + 취소 버튼. 취소·실패해도 편집 데이터와 화면은 그대로다(별도 장면이므로 원복할 것이 없음).
- 내보내기 중 메모리 해제: 렌더 타깃·임시 장면을 작업마다 정리.
- 미리보기 창은 탭이 보이지 않을 때 그리지 않는다.
- 내보내기는 Plan을 절대 수정하지 않는다(읽기 전용). 되돌리기 기록에도 남지 않는다.
