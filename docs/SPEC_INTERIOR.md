## 1. 왜 (목적과 원칙)

### 1-1. 목적
- 최종 목표: **설치 없는 웹 기반 3D 인테리어 시뮬레이터 + 이미지·게임 에셋 변환 플랫폼**.
- "유니티를 그대로 쓰는 것"이 아니라 **유니티처럼 쓸 수 있는 우리만의 프로그램**을 만든다.
  - 유니티 빌드에는 편집 화면(Hierarchy, Inspector, 기즈모)이 없어서, 유니티를 써도 편집기는 결국 다시 만들어야 한다 → 웹을 메인으로 결정.

### 1-2. 방향을 바꾼 이유
- 처음 프로젝트(그림 캐릭터 → 관절 → 포즈 변경)는 포즈를 바꿀 때 몸이 딸려오는 문제 등으로 품질이 안정되지 않았다.
- 여러 안(A~D) 중 **C안: 2D 평면도 → 3D 인테리어**를 선택했다.

### 1-3. 지키는 원칙
| 원칙 | 내용 |
|---|---|
| 100% 무료·오픈소스 | 유료 API·유료 에셋·유료 모델 사용 안 함. 결과물 저작권 자유 |
| 계산과 화면 분리 | 규칙·계산은 화면 없는 순수 함수, 모두 자동 테스트 |
| 단위 cm | 내부 데이터는 전부 cm. 외부 3D 파일로 쓸 때만 m로 변환 |
| 기존 기능 보호 | 기존 파일·테스트를 함부로 다시 쓰지 않음. 새 기능은 새 모듈에 |
| 사용자가 직접 확인 | 바뀐 것은 매번 웹 페이지(아티팩트)로 올려 테스터가 확인 |
| 쉬운 설명 | 짧고 단계별로, 쉬운 한국어 |

### 1-4. 범위에서 뺀 것 (확정)
- 3D 사람 모델링, 골격·리깅·포즈, 기존 2D 캐릭터 도구
- 유니티 전용 연동의 **추가 개발** (기존 유니티 코드는 지우지 않고 동결)
- 다각형 바닥, 계단 자리 바닥 뚫기, 층별 천장 높이 상속 (1단계 제외 확정)

## 5. 무엇을 (기능 명세)

### 5-1. Skela Room v1 편집기

**화면 구성 (유니티와 대응)**
| 영역 | 유니티에서는 | 기능 |
|---|---|---|
| 위 메뉴 | | 평면/3D/걷기, 되돌리기·다시하기, 템플릿, 저장·불러오기, 유니티로 보내기 |
| 왼쪽 "가구 넣기" | Prefab | 가구 버튼 → 방 가운데에 넣고 선택 |
| 왼쪽 "방 구성" | Hierarchy | 가구·벽·문창문 목록, 눌러서 선택 |
| 가운데 화면 | Scene | 도구: 선택·이동, 벽 그리기, 문, 창문, 이동·회전 화살표 |
| 오른쪽 "속성" | Inspector | 가구: 가로·깊이·높이·회전·위치·색, 90° 돌리기, 복제, 기본 크기, 삭제 / 벽: 길이·높이·두께, 문·창문 넣기 / 문창문: 폭·높이·위치 / 선택 없음: 방 이름, 바닥색·벽색, **넓이(m²·평)** |

**보기**
| 보기 | 내용 |
|---|---|
| 평면 | 위에서 본 직교 카메라, 그림자 끔, 끌어서 화면 이동 |
| 3D | 궤도 카메라. 카메라 쪽 벽은 반투명(30cm 여유로 깜빡임 방지) |
| 걷기 | 눈높이 160cm, W A S D / 화면 화살표 버튼, 벽 충돌(반경 22cm), 현관 안쪽에서 시작 |

**편집 규칙**
- 가구 끌기: 5cm 격자. 끄는 동안 카메라 조작 막음.
- 벽 그리기: 10cm 격자, 기존 벽 끝점 25cm 안이면 붙음, 거의 수평·수직이면 곧게. 길이를 cm로 표시.
- 문·창문: 벽 60cm 안을 누르면 들어감. 다른 문·창문과 겹치면 거부.
- 자동 저장: 브라우저 저장소(localStorage). 64평 전용 페이지는 저장 칸을 따로 씀.
- 단축키: V 선택, L 벽, O 문, N 창문, W 이동 화살표, E 회전 화살표, R 90° 돌리기, Del 삭제, F 전체 보기, Ctrl+Z / Ctrl+Y.

### 5-4. v2 시제품 (1단계 + 2단계 설계 구현, 별도 페이지)

**층 (1단계)**
- 화면 위 **[1F] [2F] [+] [쌓아 보기]** 탭. 편집은 고른 층 하나만 한다.
- 새 층: 지금 층의 벽·문·창문만 복사한 빈 층. 왼쪽 층 목록에서 순서 바꾸기, 복제, 삭제(두 번 눌러 확인, 마지막 1층은 지울 수 없음), 이름 바꾸기.
- **쌓아 보기**: 층 순서 × 260cm 높이로 쌓아서 보여주는 보기 전용 모드. 바닥은 뚫지 않는다.
- 가구마다 **보이기 / 잠금 / 내보내기에 포함** 설정. 잠긴 가구는 옮기기·돌리기·삭제가 막힌다.
- 예전(v1) 파일을 붙여넣으면 **1F 하나짜리 프로젝트로 자동 변환**. 붙여넣은 원본은 바꾸지 않는다. v2 자동 저장 칸은 v1과 따로 쓴다.
- 처음 열면 예시: 복도형 64평 2층 집(1F에 계단, 2F는 침실 위주) + 카메라 3개.

**가상 카메라 (2단계)** — ⏸ **2026-11-27 사용자 요청으로 화면에서 꺼 둠** (`v2/main.ts`의 `CAMERA_ENABLED = false`). 코드·테스트·저장된 카메라 데이터는 그대로 있고, `true`로 바꾸면 아래 기능이 다시 켜진다. 꺼 둔 동안 이미지 내보내기는 "지금 3D 화면 시점"으로만 찍는다.

- 편집 카메라(지금 화면)와 **가상 카메라(촬영용 시점 저장)**를 분리했다. 연결은 "현재 시점으로 만들기/덮어쓰기"와 "카메라로 보기"뿐이다.

| 프리셋 | 투영 | 각도 | 기본 출력 |
|---|---|---|---|
| 인테리어 | 원근, 화각 60° | 눈높이 150cm에서 110cm 높이를 봄 | 컬러 PNG |
| 아이소메트릭 | 직교 | 방위 45°, 내려보기 35.26°(정등각) | 컬러 PNG |
| 일러스트 2:1 | 직교 | 방위 45°, 내려보기 26.57°(게임 2:1) | 컬러+선화, 투명 |
| 탑다운 | 직교 | 바로 위, 화면 위 = 평면도 위 | 컬러 PNG |
| 1인칭 | 원근, 화각 70° | 현관 안쪽 눈높이 160cm | 컬러 JPG |

- 직교 카메라는 방의 8개 모서리가 화면에 들어오도록 **자동 맞춤**(여백 8%).
- 카메라를 고르면 **미리보기 창**이 뜨고, **카메라로 보기**를 누르면 찍힐 범위가 틀로 표시된다.
- **카메라 아이콘 조작**: 몸통을 누르면 선택, 몸통을 끌면 자리 이동, 작은 공을 끌면 바라보는 곳 이동. 직교 카메라는 몸통을 끌면 보는 점을 중심으로 돌고, 다 돌린 뒤 범위를 다시 맞춘다.
- **카메라 안에서 직접 조종**("카메라로 보기" 상태): 끌어서 둘러보기(직교는 보는 점 중심 회전), W A S D 이동, Q·E 높이, Shift 빠르게, 휠·−/+ 버튼 확대(원근은 화각, 직교는 범위). 폰은 화면 화살표. 손을 떼면 한 번만 저장(되돌리기 한 단계).
- **찰칵(촬영 모드)**: 화면 아래 동그란 버튼 또는 Space. 카메라로 보는 중이면 그 카메라 설정(형식·크기·비율)으로, 3D·걷기·평면이면 지금 화면을 FHD PNG로 바로 찍어 저장한다. 찍은 사진은 잠깐 미리보기로 남고 "다시 저장"할 수 있다.
- 카메라를 고르면 그 카메라가 있는 층으로 자동 이동한다. "현재 시점"은 평면이면 탑다운, 걷기면 1인칭으로 만든다.
- 속성: 이름, 투영, 화각 / 보이는 세로(cm), 비율(16:9·3:2·4:3·1:1·9:16), 앞쪽 벽(자동 숨김/그대로), 카메라 X·Y·높이, 보는 점 X·Y·높이, 기본 출력 형식·크기·투명.
- 검증: 화각 20~100°, 직교 범위 50cm 이상, 위치=보는 점이면 앞쪽 1m로 보정, 이름 비면·중복이면 자동 이름, 카메라 최대 50개, 없는 층이면 첫 층으로.

**내보내기 (2단계)**
| 종류 | 형식 | 크기·옵션 |
|---|---|---|
| 이미지 | PNG, JPG, 투명 PNG, 선화, 컬러+선화 | HD 1280 / FHD 1920 / QHD 2560 / 4K 3840(긴 변), 최대 4096 |
| 가구 스프라이트 | 투명 PNG (2:1 각도), 빈 곳 자동 자르기(여백 8px) | 고른 가구 1개 또는 층의 모든 가구, 여러 장은 ZIP |
| 3D 파일 | GLB, OBJ+MTL | 프로젝트 전체(층 쌓기) / 현재 층(바닥 높이 0) / 고른 가구(바닥 가운데 원점, 회전 0) |

- 내보내기에서는 숨김·제외 가구가 빠진다. 카메라 쪽 벽은 잘라낸다(설정에 따라).
- 파일 이름: `{프로젝트}_{층}_{카메라}_{가로}x{세로}.png` 규칙, 금지 문자는 `_`로 바꾸고 최대 80자.
- **저장**: 저장 버튼 → claude.ai의 저장 확인 창(`downloads` 기능). 일반 웹사이트에서는 브라우저 다운로드.
  - claude.ai는 GLB·OBJ 확장자를 저장할 수 없어서, 3D 파일은 **ZIP(파일 + README)**으로 묶어 저장한다.

### 6-1. 기술
| 분야 | 사용 | 비용 |
|---|---|---|
| 언어·빌드 | TypeScript 7, Vite 8 (React 없이 순수 TS) | 무료 |

### 6-2. 구조
```
[순수 계산 — 화면 없음, 테스트]                    [화면]
Plan.ts ─┬─ geometry.ts ─┬─ unityExport.ts ──▶ studio/main.ts (v1)
catalog.ts┘  templates.ts ┘                     │
                                                 ▼
v2: project.ts · camera.ts · scene2.ts ·      v2/main.ts (v2 시제품)
    exportJob.ts · zip.ts · catalog2.ts         └ 내보내기 전용 장면(편집 장면과 분리)
```
- 상태는 **불변 객체**. 바뀔 때마다 새 객체를 만들고, 되돌리기는 객체 참조만 쌓는다(`undoManager`).
- v2는 기존 파일을 고치지 않고 감싸서 쓴다. 기존 계산은 그대로 쓰고 새 규칙만 v2 폴더에 둔다.

### 6-3. 좌표와 단위
| 어디 | 규칙 |
|---|---|
| 평면도 | cm, **x 오른쪽 +, y 아래쪽 +**, 회전은 위에서 봐서 시계 방향 + |
| three.js 화면 | (x, 높이, y). `rotation.y = -각도` (거울상 없음) |
| 3D 파일 (GLB·OBJ) | (x/100, 높이/100, y/100) m, 오른손, Y가 위, 1 = 1m, 가구 앞면 +Z |
| 유니티 | (x/100, 높이/100, **-y/100**) m, 회전 그대로 (왼손 좌표계) |
| 층 높이 | 층 순서 × 260cm |

### 6-4. 화면 규칙
- **떨림(Z-파이팅) 방지**
  - 가구 안의 i번째 상자를 사방 i×1mm 키워서, 같은 평면에 겹치는 면이 없게 한다.
  - 벽 끝은 두께 절반보다 1mm 덜 늘린다. 벽마다 높이를 1mm씩 다르게 한다.
  - 바닥 격자는 바닥 아래(-2.5cm). 카메라 가까운 면 10cm.
  - 3D 파일 원점은 키우기 전 원래 크기로 계산한다.
- **벽 숨김**: 편집 3D는 카메라 쪽 벽 반투명, 가상 카메라·내보내기는 카메라 쪽 벽을 숨김. 30cm 여유로 깜빡임을 막는다.
- **그림자**: 해 방향 조명, 그림자 범위를 방 크기에 맞춤. 평면 보기에서는 끔.

### 6-5. 내보내기 방식
1. 편집 화면은 건드리지 않고 **내보내기 전용 장면**을 새로 만든다(도우미·격자 없음). 끝나면 버린다.
2. 큰 이미지는 **2048px 이하 조각(타일)**으로 그려서 이어 붙인다. 조각 합 = 전체 크기.
3. 선화: 상자 모서리(30° 이상 꺾인 곳)를 직접 선으로 뽑는다. 면은 살짝 뒤로 밀어서 가려진 선을 숨긴다. 선 굵기는 긴 변 1920 기준 1.5px에 비례.
4. 스프라이트: 가구 하나만 남긴 장면 → 2:1 카메라로 맞춤 → 512px 투명 렌더링 → 불투명 영역만 잘라내기.
5. 3D: 상자를 m 단위 메시로 만들고 `프로젝트 → 층 → 벽/문·창문/가구 → 가구 묶음 → 부품` 구조로 내보낸다. 색마다 재질 하나. OBJ는 영문 이름 + 직접 만든 `.mtl`.
